# ADR-0001：fa-im 模块优化实施方案

- 状态：提案
- 日期：2026-09-16
- 范围：`fa-im` 后端与 `frontend/apps/admin/features/fa-im-pages` 前端

## 背景

当前 IM 已具备会话、群聊、消息、已读状态和 WebSocket 基础能力，但仍存在以下上线风险：

- 会话、消息和群成员接口缺少统一的数据权限校验。
- 部分 SQL 使用 MySQL 方言，无法保证 PostgreSQL 正常运行。
- 群聊成员、管理员、单聊唯一性等业务规则主要依赖前端。
- 前端消息状态更新存在并发覆盖，部分群聊交互和 Hook 实现需要返工。
- 缺少 fa-im 专项测试和数据库升级验证。

## 开发说明

### 1. 会话权限和 API 收敛

- 增加统一的 `requireParticipant` 和 `requireManager` 业务校验。
- 消息查询必须关联 `im_participant`，不能仅按 `conversationId` 查询。
- 发送消息时由服务端确定发送人，不接受客户端伪造 `senderId`。
- 消息、参与者和已读状态只保留业务必需接口，不直接暴露完整通用 CRUD。
- 群聊管理接口必须校验会话类型和当前用户权限。

### 2. 参数校验

- 将 Forest 的 `NotNull` 替换为 `jakarta.validation` 注解。
- 集合使用 `@NotEmpty`、`@Size`，标题和内容使用 `@NotBlank`、`@Size`。
- `conversationId` 统一使用 `Long`。
- 所有业务入口都做校验，不能只依赖前端限制。

### 3. MySQL/PostgreSQL 兼容

- 修复 `IFNULL`、带表别名更新列和硬编码 `limit`。
- 需要方言差异的 SQL 分别放入 MySQL/PostgreSQL 脚本或 Mapper。
- 新增表结构变更时分别提供两种数据库版本脚本。
- 不修改已发布的 `1.0.0` 基线脚本，不使用 `DROP TABLE`、`TRUNCATE` 等清库操作。

### 4. 数据模型和查询性能

- 未读数和撤回状态设置明确的非空默认值。
- 增加消息按会话分页、参与者按用户/会话查询所需索引。
- 单聊使用可唯一约束的双方标识，避免依赖 JSON 文本判断重复。
- 群聊名称以会话表为准，不在参与者表保存容易失效的副本。

### 5. 群聊和消息业务

- 创建群聊时自动确保当前用户为成员，并校验成员存在、去重和最小人数。
- 移除成员时禁止绕过管理员规则，不能移除管理员或造成无成员群聊。
- 消息内容按消息类型统一协议，文件消息统一保存 `fileId`、文件名、大小和扩展名。
- 已读更新只允许操作当前用户自己的参与者记录。

### 6. WebSocket 通知

- 新消息、添加成员、移除成员、退出群聊和重命名使用明确的事件类型。
- 数据库事务提交成功后再推送通知。
- 通知失败不能影响消息落库，客户端需要通过会话列表或未读数接口补偿刷新。

### 7. 前端状态和交互

- 消息列表统一使用函数式状态更新，临时消息按临时 ID 替换为服务端消息。
- 切换会话时避免旧请求覆盖当前会话，可使用请求序列或取消请求。
- 会话列表、选中会话和详情面板使用同一份更新逻辑。
- 修复群成员查看更多、重复回调、异常头像 JSON 和条件 Hook。
- 可点击元素使用按钮或补充键盘可访问性，统一处理文件上传失败。

## 验收标准

- 非会话成员无法查询、发送或修改该会话数据。
- 非管理员无法执行受限群聊操作。
- MySQL 和 PostgreSQL 均可完成建表、会话查询、消息发送、分页和已读更新。
- 快速连续发送消息不会出现前端消息丢失或顺序错乱。
- 群成员变更和群名变更能同步到相关在线用户。
- 关键权限、并发和分页场景有自动化测试覆盖。

## 暂不处理

- 群公告、管理员转移、消息撤回、语音/表情消息和好友体系暂不纳入本轮实现。
- 暂不引入新的消息队列、状态管理框架或文件传输依赖；优先复用现有 Spring、MyBatis-Plus、WebSocket、React 和 Ant Design 能力。
